1 FrostRoute Backend — Code Analysis

Before comparing with research papers, it is important to fully understand what our own backend does. The FrostRoute C program reads a graph description from stdin, runs Dijkstra's algorithm, and outputs a rich JSON object to stdout — making it usable as a backend engine for any frontend (web, mobile, visualizer).

Core Design Decisions in the Code

/* Input format (stdin): */ n source target m // n = nodes, m = edges u v w // m lines: edge u-v with weight w (made bidirectional) /* Output format (stdout): */ { "ok": true, "source": 0, "target": 5, "distance": 14, // shortest path cost (null if unreachable) "path": [0, 2, 4, 5], // reconstructed shortest path "visitOrder": [0,1,2...], // nodes in the ORDER Dijkstra visited them "distances": [0,3,5,null] // shortest dist from source to EVERY node }

Key Implementation Features

Adjacency List via Linked List
Edges stored as chained Edge structs using a static pool (no malloc overhead). Efficient for sparse graphs.
O(V²) Dijkstra (Linear Scan)
Uses a simple for-loop scan to find minimum instead of a heap. Correct and simple — suitable for V ≤ 256.
Parent Tracking + Path Reconstruction
parent[] array enables tracing back the exact shortest path from target to source, then reversing it.
Visit Order Capture
visitOrder[] records each node the moment it is finalized — enabling step-by-step algorithm replay in the frontend.
All-Node Distances Output
distances[] in JSON gives shortest distance from source to every reachable node — not just the target.
Negative Weight Clamping
Any negative edge weight is silently clamped to 0. FrostRoute is intentionally designed for non-negative weights only (stated in the file header comment).

2 Research Paper 1 — Shortest Path Finding Visualizer

P1
Shortest Path Finding Visualizer — An E-Learning Web Tool
Haldavanekar, Mahadwad, Dighe, Suryawanshi, Rai · IJRASET 2023 · DOI: 10.22214/ijraset.2023.53207

What the Paper Proposes

This paper describes building a web-based e-learning visualizer for shortest path algorithms. It implements Dijkstra and DFS on a grid (lattice) structure where each cell is a node connected to its 4 neighbors (up, down, left, right). The goal is educational — helping students see how the algorithm traverses nodes through animation. Built using HTML, CSS, JavaScript, and React.

  • Grid/lattice-based graph (not a general weighted graph with arbitrary edges)
  • All nodes connected to exactly 4 neighbors — equal weight movement
  • Algorithm Module computes shortest path; Node Module handles animation; Path Visualizer handles mouse interactions
  • Visualization only — no JSON output, no external API interface
  • Includes DFS as second algorithm alongside Dijkstra
  • Runs entirely in the browser — JavaScript only, no backend

3 Research Paper 2 — Optimized Dijkstra for Networked Systems (IoT)

P2
Optimized Implementation of Dijkstra's Algorithm for Efficient Shortest Path Finding in Networked Systems
IJRASET 2024 · DOI: 10.22214/ijraset.2024.65444

What the Paper Proposes

This paper focuses on optimizing Dijkstra's algorithm for dynamic, large-scale networked systems such as IoT networks, smart city traffic systems, and telecommunications. It identifies the classical Dijkstra as a starting point and introduces optimizations to handle real-time data streams and adaptive routing. The paper evaluates performance under dynamic conditions where graph topology changes at runtime.

  • Targets dynamic graphs — edge weights can change during runtime (live traffic, IoT sensor data)
  • Uses a priority queue (min-heap) for O((V + E) log V) performance — better than O(V²)
  • Incorporates real-time data streams — the graph is updated with live sensor/network data
  • Focuses on resource allocation and energy consumption in IoT contexts
  • Applied to smart city routing and telecommunications — practical engineering focus
  • Does not provide structured JSON output or a visualizer — purely algorithmic optimization paper

Comparison: Paper 2 vs FrostRoute

Aspect Paper 2 (IoT Optimization) FrostRoute
Graph Dynamism Dynamic graph — edge weights change at runtime; algorithm re-runs on updates Static graph — graph is fully defined at input time; one computation per invocation
Priority Queue Uses min-heap priority queue — O((V+E) log V) time complexity Uses linear scan over all nodes — O(V²) time complexity; simpler, correct for small graphs
Target Scale Large-scale real-world IoT networks with thousands of nodes Small-to-medium graphs (≤256 nodes, ≤4096 edges) — ideal for academic/visualizer use
Application Domain IoT device routing, smart city traffic, telecommunications General-purpose shortest path — works for any undirected weighted graph scenario
Output Format Performance metrics and routing tables — no JSON API output JSON with path, visitOrder, distances[], distance — plug-and-play backend API
Visit Order Export Not tracked or exported — optimization paper only visitOrder[] tracked and exported — enables step-by-step algorithm replay
Implementation Language Not specified (theoretical + pseudocode) Fully implemented in C — production-ready compiled binary
Negative Weights Explicitly excluded (non-negative only) Explicitly excluded; negative weights silently clamped to 0 as a safety measure
✅ What FrostRoute adds beyond Paper 2: FrostRoute provides a complete working implementation with structured JSON output — something Paper 2 lacks. While Paper 2 achieves better time complexity (O((V+E)logV) via heap), FrostRoute trades this for simplicity and three additional data outputs: visitOrder[], path[], and all-node distances[] — making it a complete visualizer backend rather than just a routing engine. FrostRoute also handles the full stdin→JSON pipeline making it language-agnostic and directly callable from any frontend.
⚠️ Where Paper 2 is more advanced: Paper 2's use of a priority queue and dynamic graph updates makes it more suitable for production-scale real-time systems. FrostRoute's O(V²) approach would be slower for graphs with thousands of nodes — an acknowledged trade-off for simplicity in a DAA visualization project.

4 Research Paper 3 — Comprehensive Review of Shortest Path Algorithms for Network Routing

P3
A Comprehensive Review of Shortest Path Algorithms for Network Routing
AJRCOS 2025 (Under Peer Review) · SDI Article · Covers Dijkstra, Bellman-Ford, A*, ACO, Hybrid and AI-based methods

What the Paper Proposes

This is a survey/review paper that classifies and compares all major shortest path algorithms used in network routing. It categorizes algorithms into three families: classical (Dijkstra, Bellman-Ford, Floyd-Warshall), heuristic (A*, Greedy Best-First, Ant Colony Optimization), and hybrid/AI-driven (reinforcement learning, blockchain-based routing). It discusses their applications across IoT, VANETs, and SDNs.

  • Identifies Dijkstra as optimal for non-negative weight graphs in link-state routing protocols (OSPF, IS-IS)
  • Highlights Dijkstra's limitation: cannot handle negative edge weights — Bellman-Ford needed for that
  • Discusses A* as a heuristic improvement — uses domain knowledge (heuristic h(n)) to guide search faster
  • Discusses Ant Colony Optimization and Reinforcement Learning as advanced alternatives
  • Notes that classical algorithms like Dijkstra are the foundation of all modern routing — still the most widely used in practice
  • Identifies key challenges: scalability, dynamic topologies, security (route hijacking), energy efficiency
  • Does NOT implement any algorithm — purely a theoretical review paper

✅ What FrostRoute adds beyond Paper 3: Paper 3 is a survey with no code. FrostRoute takes the classical Dijkstra that Paper 3 describes and extends it into a complete, production-usable backend with: a clean stdin/stdout interface, structured JSON API output, full path reconstruction, visit order tracking for animation, all-node distances, and proper error handling with graceful JSON error responses. FrostRoute is essentially the engineering realization of what Paper 3 only theorizes.

6 What FrostRoute Uniquely Contributes

After analyzing all three papers, the following features exist only in FrostRoute and are not found in any of the three research papers:

🔷 Structured JSON API Contract
FrostRoute outputs a well-defined JSON object with ok, distance, path, visitOrder, and distances fields. None of the papers define or implement such an interface. This makes FrostRoute a plug-and-play backend for any frontend technology.
🔷 visitOrder[] — Algorithm Replay Data
The sequence in which Dijkstra finalizes each node is captured in visitOrder[]. This is the exact data a frontend needs to animate the algorithm step-by-step. No paper exports this as structured data.
🔷 Graceful Error Handling in JSON
Invalid input produces {"ok":false,"error":"bad header"} — a machine-readable error response, not a crash or exception. Unreachable targets produce "distance": null. No paper implements this.
🔷 C Language Static Memory Model
Using a static edge pool (no dynamic allocation) and fixed-size arrays, FrostRoute avoids memory fragmentation and heap allocation failures — important for a stable backend engine. None of the papers use this architecture.
🔷 Negative Weight Clamping
Rather than crashing or producing wrong results on negative weights, FrostRoute clamps them to 0 and continues. This is a practical defensive design choice not found in any of the papers.
🔷 Dual-Direction Edge Addition
Each undirected edge u→v is stored as both u→v and v→u in the adjacency list, making the graph truly undirected — correctly handled without requiring the input to list both directions.

🏁 Summary Verdict

FrostRoute sits at the intersection of what three different papers separately attempt — and goes further than each in its own way:

  • vs Paper 1 (Visualizer): FrostRoute generalizes from a fixed grid to any weighted graph, decouples backend from frontend, and exports structured data (visitOrder, distances) instead of just rendering pixels.
  • vs Paper 2 (IoT Optimization): FrostRoute trades the O((V+E)logV) heap for a simpler O(V²) scan, but compensates with richer output — a full JSON API including path reconstruction, visit ordering, and all-node distances that Paper 2 never provides.
  • vs Paper 3 (Survey): FrostRoute is the engineering realization of what Paper 3 only theorizes — a working, error-handling, API-friendly Dijkstra implementation that correctly addresses the algorithm's non-negative weight constraint and produces a complete SSSP result.
  • Unique contributions: JSON API contract, visitOrder[] export, JSON error flags, static memory model, negative weight clamping — all absent from the literature reviewed.
